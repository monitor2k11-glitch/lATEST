Data source
Control where the seven CSVs above are loaded from. In server mode the console fetches each file by name from the base URL below on load (and on refresh, if enabled) — nothing is read from a local disk path by the browser itself.

A browser cannot open C:\Data\ directly — that path only means something to the machine running the web server. Point the web server's document root (or a virtual directory) at C:\Data\ so each file is reachable over HTTP as baseUrl + filename, e.g. /data/break_details.csv → C:\Data\break_details.csv. The exact file names expected are set per schema in File Loader / Data Import above.

Activity logging
Every load, reload, error and notification attempt is logged. Choose how much detail to keep and, in server mode, where to send it — the browser POSTs each entry as JSON to the endpoint below, and the web server is responsible for appending it to a file under C:\Logs\.

Without a reachable log endpoint, entries still appear below and can be downloaded, they just never reach C:\Logs\. A minimal server endpoint only needs to accept a JSON POST of {time, level, message, meta} and append one line to the day's log file.

SMTP configuration

Browsers cannot speak SMTP directly. Configure a relay endpoint here — a small internal API/serverless function that accepts a JSON payload and sends it on via your SMTP host — and the console will POST to it. Without a relay endpoint, "Send test email" will show you the exact payload instead of sending it.

MS Teams webhooks

Teams incoming webhooks are called directly from the browser. Some tenants block cross-origin calls to webhook.office.com; if a test fails silently, proxy it through your relay endpoint instead.
